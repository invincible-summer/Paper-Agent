# 论文横向对比工作流

目标：产出一张**有据可查**的结构化对比表 + 一段差异分析，帮用户看清多篇论文在每个维度上的异同。

## 执行步骤

1. **确定对比对象**：用户指定了 paper_ids 就用指定的；未指定时默认核心集中相关性最高的 5 篇。超过 5 篇时挑最相关的 5 篇，并用一句话向用户说明取舍。
2. **判定论文类型，自选维度**（不要机械套固定维度）：
   - 方法类论文：研究问题 / 核心方法（具体到模块名、技术路线）/ 数据与评测（数据集、指标、关键数值）/ 核心结论 / 局限
   - 综述类论文：覆盖范围 / 分类框架 / 指出的挑战 / 未来方向
   - 理论类论文：假设条件 / 主要定理或命题 / 证明思路 / 适用边界
   - 混合对比时取维度并集，某篇不适用的格子写"—"
3. **补齐素材**：网络论文只能使用当前有效摘要；摘要未报告的方法细节、实验数字或数据集一律写“摘要证据不足，请上传原文”，不得调用网络全文。用户上传论文后，才用 `deep_read(attachment_ids=[...], focus="实验数据集与指标数值")` 获取全文级证据。
4. **定向补缺**：表格仍空缺的维度用 `ask_papers(query=..., paper_id=...)` 逐篇定向补查。控制成本：每篇论文至多 2 次定向问答；补不到就标"未报告"，不要反复重试。
5. **产出对比表**：markdown 表格，列为论文（[paper_id] 简写标题），行为维度。每个单元格的内容必须来自已检索材料并带 [paper_id] 引用；有数字必须写数字。
6. **差异分析**（表后 3-5 句）：哪篇适合什么场景、方法上的关键取舍（如精度 vs 效率、通用 vs 专用）、如果用户要做后续研究该以哪篇为基线。

## 硬规则

- 表格只填有据可查的内容；查不到写"未报告"，**禁止编造数字、数据集名、方法名**。
- 每个事实单元格必须带 [paper_id] 引用，id 只能来自检索结果。
- 用用户的语言输出。
- 如果素材只够填少数维度，明说证据不足，给出能对比的部分；需要全文级结论时引导用户上传原文。
