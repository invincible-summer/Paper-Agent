# 格式合规处理工作流

目标：把"格式要求"变成一份逐项对照结论 + 可执行修改清单，并在用户需要时导出规范稿。

## 执行步骤

1. **拿到两类输入**：
   - 被检论文：会话中的上传附件（没有就先请用户上传，支持 pdf/docx/tex/txt/md）
   - 格式要求：用户粘贴的要求文本（作为 `spec`），或上传的格式说明/模板文件（也在附件里，用 attachment 参数区分两份文件）
2. **确定性检查**：调用 `check_format(attachment=<论文>, spec=<格式要求原文>)`，拿到逐条对照结果：
   - 可文本化检查项（摘要字数/关键词个数/正文规模/参考文献 GB/T 7714/图表编号/引用风格）→ 直接给结论
   - 排版项（字体字号/行距/页边距/页眉）→ 报告里已列入"需人工核对"，如实转达，不要编造结论
3. **定性补充**：check_format 覆盖不到的格式语义（如"图题在图下方""表题在表上方""章节标题层级是否规范"），用 `ask_papers` 对附件取证后判断（≤3 次，控制成本）。
4. **输出**（用户语言，markdown）：
   - 合规总览表：每条要求 → ✅合规 / ❌不合规（附实测值）/ 🖐需人工核对
   - 修改清单：不合规项按改动量排序，每条给具体改法
   - 人工核对清单：排版项 + 核对方法（Word 里看哪里）
5. **导出（可选）**：用户要修改说明或规范稿时，用 `export_manuscript` 导出 docx/tex/md。参考文献格式转换可配合 `citation_export`（GB/T 7714）。

## 硬规则

- 结论只基于 check_format 的计算结果与亲自取证的文本；没查到的项标"未检查"，不猜。
- 格式要求与实测冲突时，以用户给的 spec 为准（不是以工具默认阈值）。
- 一次只对照一份论文 + 一份格式要求；用户给了多份先确认对象。
