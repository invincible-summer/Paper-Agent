# 论文结构推荐工作流

目标：按论文类型与用户研究主题，给出可直接动笔的章节骨架（章节 + 每章要点 + 篇幅占比 + 章间逻辑）。

## 执行步骤

1. **判型**：先弄清用户的论文类型与场景，不清楚就问一句（这是最影响骨架的变量）：
   - **实证研究**（CS/理工期刊会议）→ IMRaD：摘要 / 引言 / 相关工作 / 方法 / 实验 / 结论
   - **综述论文** → 引言 / 背景 / 分类体系 / 分主题综述（若干）/ 讨论 / 未来方向 / 结论
   - **系统论文** → 引言 / 相关工作 / 需求与设计 / 实现 / 评估 / 结论
   - **本科/硕士毕业论文（CS）** → 摘要(中英) / 绪论 / 相关理论与技术 / 系统分析与设计 / 系统实现 / 测试 / 总结与展望
   - **社科/人文毕业论文** → 摘要 / 绪论(问题提出) / 文献综述 / 理论框架 / 研究设计 / 分析与讨论 / 结论
2. **生成骨架**：每章给出
   - 章节名 + **内容要点**（这章写什么、不写什么）
   - **篇幅占比**建议（如方法 25-30%、实验 20-25%）
   - 与前后章的**逻辑承接**（引言的缺口 → 方法的动机；方法的模块 → 实验的消融）
3. **主题化落地**：把骨架里的占位换成用户的实际主题（"第三章 基于 <用户方法> 的 <任务> 系统设计"）。网络论文只可用有效摘要理解主题/方法概况，不能据此声称其章节结构；只有用户上传范文后，才可用 `deep_read(attachment_ids=[...])` 或定向 `ask_papers(attachment_id=...)` 比较真实结构（最多 2 次）。
4. **衔接**：骨架交付后提示可继续：`paper_writing`（初稿写作模式，按此骨架分节起草）、`related_work`（先写相关工作章）、写完上传草稿后用 `check_structure` 复查结构、`check_format` 查格式。

## 硬规则

- 骨架不超过两级（章/节），不要替用户把整篇论文都规划死——留白给研究本身。
- 篇幅比例是建议值，明说可根据内容调整。
- 不虚构"标准模板"：类型判不准就先问，不硬套。
