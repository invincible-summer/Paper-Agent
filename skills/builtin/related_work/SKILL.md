# 相关工作章节写作工作流

目标：把会话里的论文集组织成一段可直接放进论文的"相关工作"——有叙事线、有批判性、收尾引出用户自己的研究位置。

## 执行步骤

1. **备料**：需要核心集论文的结构化摘要，没有就先确认是否有有效摘要；需要全文证据时请用户上传文件后再 `deep_read(attachment_ids=[...])`。有研究地图则用主题簇做组织骨架；没有就自己按方法流派/问题子类分组（2-4 组为宜）。
2. **确认用户的研究位置**：用户给过自己的构想/论文主题时，相关工作收尾要扣上去；没给过就用一句话问清"你的工作与这些文献的关系是什么"，或按通用空白收尾。
3. **写作**（用户语言）：
   - **按主题组织，每段一个流派**：代表工作 [paper_id] → 演进逻辑（谁解决了谁的什么问题）→ 该流派的共性局限。**禁止逐篇罗列**（"A 做了…B 做了…C 做了…"是相关工作的大忌）。
   - **段间衔接**：用对比/递进过渡（"与上述方法不同，另一类工作…"）。
   - **收尾段**：归纳出现有工作的空白，明确引出用户研究（或通用研究）的位置与机会。
   - 长度默认 3-5 段；用户指定字数/段数则遵循。
4. **引用与交付**：正文引用用 [paper_id] 占位；成稿后提醒用户：可用 `citation_export` 生成 BibTeX 或 GB/T 7714（毕业论文）格式的参考文献列表，cite key 与正文一一对应。
5. **自检**：每个被引工作都在会话论文集内；没有任何凭模型印象虚构的文献；每篇被引工作的描述与其摘要不矛盾。

## 硬规则

- 只能引用会话内论文集里的工作；禁止虚构或凭记忆补文献。
- 描述必须忠于证据（摘要/深读材料）；拿不准的贡献描述写保守些。
- 是"写作"不是"摘要拼接"——叙事线和批判性必须有。
