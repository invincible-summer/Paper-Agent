# 阅读工作台实施记录

对应设计：`docs/READING_WORKBENCH_PROPOSAL.md`。用户于 2026-09-05 授权开始实施，当前 Goal 为完成 A+B 可用闭环，不部署生产。

## 交付范围

独立 PDF 原版阅读；从当前会话附件进入；安全会话绑定（包括尚未发消息的附件）；页码恢复、稳定锚点；专业翻译、当前论文选区追问、独立阅读线程；高亮/笔记/发现持久化；发现明确发布回主聊天及原文回跳。C/D 的全篇主张核验、复杂图表助读和双论文对照不属于本轮。

## 实施顺序

1. 检查现有会话历史持久化、上传权限、LLM utility、orchestrator 轮次、用户数据删除和前端路由，确定最小可兼容接入。
2. Web 阅读 SQLite 存储及类型：会话映射、文档阅读状态、锚点、笔记/发现、线程/消息；owner/session/attachment 全路径校验、版本锁及清理。
3. 会话级写锁覆盖原聊天与发现发布；实现会话绑定、PDF content/manifest、CRUD、专业翻译和阅读问答接口；问答使用隔离消息的统一 orchestrator，不写入主聊天的临时问答；取消与失败清理。
4. 独立阅读布局与 PDF.js worker/text layer、选区/高亮/页码恢复；右栏翻译问答、发现与笔记；附件入口、主聊天发现卡和引用回跳。兼顾小屏、键盘、加载/空/错误态。
5. 专业翻译/回答 prompt 注册，针对性安全/状态/并发/降级测试；PDF 交互浏览器验证使用合成文件和模拟模型。
6. 默认后端完整测试、前端 lint/build；修复阻塞；运行 Git 跟踪数据审计；更新 README 与 DESIGN；如实记录结果。

## 验收边界

- 不改变原始 PDF 排版，打开无需 LLM/VLM；全文结构未就绪也能阅读。
- 同一账号不同会话及不同账号读写隔离；文件 id/锚点/线程不可越权。
- PDF 物理页号与稳定坐标；选择文本服务端核对，无法定位不伪造精确来源。
- 原文、AI 解释、用户判断区分；翻译保留数字/变量/限定语/引用。
- 缩放、切页、刷新后可恢复；批注冲突不覆盖；发布幂等；取消不污染聊天。
- 主聊天和阅读分开记录、共享本会话材料；/v1 行为保持兼容。
- runtime 数据不提交；现有 AGENTS.md 改动保留；不修改生产手册。
