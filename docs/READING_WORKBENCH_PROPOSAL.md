# 论文阅读工作台设计提案：读到证据，留下自己的判断

状态：产品与技术设计，2026-09-05；阶段 A+B 已实现并完成本地验收，具体实现与取舍见 `READING_WORKBENCH_IMPLEMENTATION.md`。本文保留后续设计，不能将全部构想视作当前功能；当前功能以 README 与 DESIGN 为准，未进行生产发布。

## 1. 产品定位

把 Paper Agent 从“输入问题、等待回答”的工具推进为“围绕论文原文开展研究”的工作环境。聊天负责提出问题、组织资料和综合成果；阅读工作台负责理解、核对、批注和形成判断。

核心闭环：带着研究问题打开论文 → 在原文中阅读与追问 → 保存带出处的发现 → 回到对话比较、写作或汇报 → 从答案再次返回原文核验。

核心特色是可追溯的阅读成果：每条重要判断都能展开其原文、图表和适用条件。翻译、摘要与聊天服务于这条闭环。

## 2. 空间与视觉

工作台暂名“阅研”。沿用纸墨书院的黛青、暖灰与朱砂，但减少装饰：周围环境柔和，PDF 本身保持白纸、原色与原版排版，图表不做夜间反色。

桌面采用可调三栏：左侧 200–240px 导航、中间弹性原文、右侧 340–420px 助读。中栏空间不足时先收起左栏；左右栏均可折叠。1440px 宽度下初始可用 216px / 弹性 / 360px，不能为了同时塞下功能把双栏论文缩到难读。

顶部：返回对话、所属会话、当前论文切换、阅读目标、视图、缩放、保存状态。左栏切换目录/图表/我的标记。右栏切换助读/发现；默认只呈现当前任务。底部轻量页码与跳转，不常驻厚重工具条。

阅读提供连续滚动、单页翻页、宽屏双页三种视图；初次默认连续滚动，记住用户选择。书籍感来自纸张留白、克制阴影与轻量翻页过渡，翻页动画不能妨碍选字、引用跳转或键盘操作。提供专注模式；小屏用单页与底部助读抽屉。

第一版 PDF 优先。DOCX/Markdown 等仍可使用现有文本阅读；不宣称在浏览器重排 DOCX 能保留原始分页。后续专门评估转换预览。

## 3. 从哪里进入

当前对话的 PDF 附件卡与文件列表增加“打开工作台”；聊天回答的原文引用可直接打开指定页和高亮；工作台顶部可切换当前会话其他 PDF。

候选路由为 `/chat/{session_id}/read/{attachment_id}`，引用使用 fragment 中的服务端 anchor id。它们是定位符，不是权限凭据。现有聊天按 history_filename 恢复，因此需要新增经过归属检查的 session_id → 历史映射，不能直接把 URL id 当磁盘路径。

上传但尚未发送消息时，先通过专门的会话初始化/附件绑定操作建立草稿会话，再进入工作台；不为取得会话 id 偷发一条模型消息。未上传全文的搜索结果提示上传原文，不自动获取网络 PDF。

## 4. 保留原文，叠加交互

PDF 原件是视觉基准。使用 PDF.js 客户端渲染页面、文本选择层和链接层，再增加自有高亮与元素热区。Docling/PyMuPDF 的结构结果用于理解与定位，不参与重排原始正文。公式、表格、图片与引用在原文中保持原貌；生成解释中的公式另行使用经过安全配置的数学渲染组件。

PDF.js 的显示层和 viewer 可作为自定义阅读器基础；页面 API 提供文本、注释与 viewport 变换。技术依据：[官方入门](https://mozilla.github.io/pdf.js/getting_started/)、[PDFPageProxy API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFPageProxy.html)。依赖版本应在实施时验证与现有 Next.js、Node、浏览器及 worker 打包兼容性后锁定。

打开 PDF 即可阅读，不等待全文结构分析或 VLM。增强能力按当前页/用户操作逐步就绪，缺失的目录或图表索引分别显示状态。扫描页仍能浏览，可框选区域做按需 OCR；OCR 结果可校正、标为识别文本，不伪装成精确原文。

双栏论文、断词、连字、旋转页和重复句是重要边界。选中后保留原始 quote 和规范化文本；模型处理前提供可展开的原文核对。无法可靠匹配句子时仅提供页级定位，提示精度下降。

## 5. 关键交互

### 5.1 专业选句翻译

选中后出现轻量操作条：翻译、解释、追问、记下。开启“划选即译”后，在选区稳定约 400ms 后自动请求，选区变化取消前次任务；不开启时点击翻译再请求。短译文出现在选区旁，长译文转入右栏，原文不被覆盖。

LLM 上下文包括原句、相邻段落、章节标题、论文领域、当前文档术语表。保留引用编号、变量、数字和限定语；直译主体与术语解释分开，避免把解释写进作者原话。多义术语给出译法依据，用户修改后对本会话内该文档后续翻译生效。

术语表优先从当前内容逐步累积，不为首次翻译强制扫描整篇。缓存包含文档版本、选区、上下文、目标语言、术语表版本、模型与提示词版本；有长度限制、去重、限流和取消。失败保留选区并允许重试，不打断阅读。

### 5.2 对着句子和图表提问

选中一句话输入“为什么成立”，输入框上方出现可见的证据标签，如“第 5 页 · 方法 · 已选 2 句”。默认范围为当前论文；可显式切换到当前会话资料，并明确其他材料是摘要还是全文证据。

回答组织为直接解释、原文依据、必要补充。每个来源按钮能返回页面并高亮。标清作者陈述、模型解释和用户笔记；证据不足时保留问题，不补造论断。

图表、公式热区 hover 仅提示可操作，点击才展开右栏。提供“怎么看”“支持什么结论”“有什么条件/局限”。公式解释优先结合文中的符号定义；不要在缺乏原文定义时补造符号含义。表格保留原图，可另看已解析数据；模型补充解释不得覆盖结构提取的数值。

### 5.3 页边讨论

当前选区或元素可建立讨论线程，页边显示小标记，点击回到对应问答。右侧只开一个活动讨论面板，避免多个漂浮聊天框遮住 PDF。

切换论文时保存当前页、选区和线程草稿；回答生成期间切换页不改变本轮证据，返回来源按钮仍指向原选区。取消、断线与重试有独立状态，未完成回复不能标为已完成发现。

### 5.4 按目标助读

顶部可选“理解方法 / 检查证据 / 准备复现 / 准备汇报”，或沿用当前对话的研究问题并允许修改。

同一篇论文据此给出短阅读路线，例如“先读任务定义 → 看主结果表 → 看消融 → 核对限制”。用户点击后再生成，不随翻页自动调用模型。每站带页码、阅读问题和完成状态；完成是用户自评，不用浏览页数冒充理解程度。

### 5.5 可带走的发现

用户把原句、图表解释或回答“记为发现”，选择贡献、证据、疑问、可复用方法之一，并可写自己的判断。

发现卡保存作者原话/数据、解释、用户判断、来源锚点、适用条件和待验证状态。原文与 AI 解释分别显示，编辑不会改写引用原句。

在“本次阅读收获”中集中整理发现、尚未解决的问题和下一步；可发送选中发现到主对话，也可导出带页码和短引文的 Markdown/DOCX。不默认复制整篇原文。

## 6. 让它有辨识度的能力

### 主张与证据对照

用户选中一条结论，点击“核对证据”，得到一张小型证据卡：作者主张 → 相关实验/论述/图表 → 适用条件 → 暂未找到的支持。理工实验论文、理论论文、综述和人文论文采用不同证据维度。

所有连线必须有原文支持；不足写“未定位到支持”，不以模型主观分数包装成可信度。用户可以纠正关系。先做用户选中的单条主张，再考虑全篇概览。

### 术语与符号随读手册

阅读时逐渐积累本篇术语、缩写与符号，记录首次定义位置、当前上下文、译法与用户修正。再次碰到可直接查看，避免反复询问。不同论文的同名符号不自动合并。

### 从阅读到研究的桥梁

保存的方法与证据能在同一会话中进入论文横评、综述提纲与组会汇报。后续增加“带着同一个问题比较两篇论文”：两边定位到各自方法或结果，并显示比较条件是否一致，而非仅输出泛化对比表。

优先级：原文交互与发现闭环先落地；主张核验作为第一个特色增强；双论文比较随后。暂缓全文自动改写、自动生成整本双语 PDF、复杂 3D 翻书和跨会话全局知识库。

## 7. 与主聊天的关系

一个会话拥有一套材料和研究目标，内部有主讨论及阅读线程。阅读线程不是新会话，不获得跨会话资料权限。

| 信息 | 阅读工作台 | 主聊天 |
| --- | --- | --- |
| 会话附件、研究目标 | 共享并可见 | 共享并可见 |
| 局部翻译与临时解释 | 保存在阅读线程/操作记录 | 不逐条插入消息历史 |
| 已保存发现与笔记 | 可编辑、定位与组织 | 显示轻量“阅读发现”入口，可按需检索 |
| 用户发送回主对话的发现 | 保留来源链接 | 形成明确的上下文卡，可继续讨论 |
| 页码、缩放、面板状态 | 保存阅读位置 | 返回工作台时恢复 |

进入阅读时按需带入主对话的研究目标、相关约束与有界摘要，不复制全部主聊天。主聊天可以按需读取同会话已保存发现；明确依赖其作答时给出引用。未保存的选句与临时问答不默默成为主聊天事实。

“发送到对话”由用户点击触发，带短摘要、原文锚点与发现 id；不自动启动新的模型任务。返回聊天保留滚动位置和草稿。主聊天引用任一发现都可一键回到原文。

## 8. 与当前代码的衔接

已确认的基础：

- `frontend/components/RightSidebar.tsx` 已能汇总当前会话附件；文档目前展示提取文本，图片走鉴权 Blob。
- `backend/app/api/v1/chat.py` 的 raw endpoint 目前仅允许图片，PDF 需要新的鉴权内容接口，不能假设直接用现有接口即可。
- `agents/session.py` 已有 `session_id`、附件与研究状态；网页请求目前按历史文件加载并保存会话。
- `agents/reader_agent.py::parse_and_understand` 和多模态层已有按页结构、元素、裁图与上传全文检索能力，但不保证已有逐句坐标，需要单独建立阅读锚点。
- `frontend/app/chat/page.tsx` 当前持有流式请求控制器。直接导航离开会影响流式状态管理，需把轮次控制移到共享会话运行服务/持久布局，不能简单复制页面。

建议新增 `frontend/components/reader/`、`frontend/stores/reader.ts`、`frontend/lib/reader-api.ts`、`backend/app/api/v1/reader.py` 和 `core/reading_store.py`。从 chat 页提取共用流式运行逻辑，阅读器用独立布局，不挤进现有 340px 文件预览栏。

PDF 内容、manifest、锚点与笔记 CRUD 使用确定性接口。候选 API 前缀为 `/api/v1/reader/sessions/{session_id}/documents/{attachment_id}`，下含 content、manifest、anchors、annotations、threads、actions；会话级 findings 与 publish-to-chat 单独管理。实施时按仓库 schema 风格细化。

翻译使用有界 utility LLM 调用，不启动通用工具循环；需要检索/工具的阅读问答仍通过统一 orchestrator，新增显式 thread/context scope，把回复写入相应阅读线程。不得复用共享 session.messages 后再尝试撤销写入。

第一版同一会话的会修改研究状态的 agent 轮次串行执行，主聊天忙时阅读问答可排队/取消；翻页与本地选择不受影响，纯翻译在全局限流内可并行。服务端负责锁和请求幂等，多标签页不能只靠前端 responding 标记。排队在界面上可见。

## 9. 数据与定位

建议独立 Web 阅读数据表，存入运行目录下的 SQLite，与 API checkpoint 隔离。至少包含 ReadingDocumentState、Anchor、Annotation、ReadingThread/Message、Finding 与 Publication 记录。所有对象经所属会话继承 owner，删除会话时按关联清理；加入用户数据管理、备份和磁盘统计范围。

Anchor 包含 attachment_id、文档 fingerprint、从 1 开始的 PDF 物理页号、可选显示页码、按未旋转页面坐标规范化的多矩形、quote/exact-prefix-suffix、可选 element_id 和定位状态。支持跨行/跨页选区；缩放旋转用统一 viewport 变换。原文变更使锚点失效，不能将旧标记静默贴到新文件。

客户端提交的选文、页码和模型返回引文均需服务端核对；未匹配内容只能作为用户提供文本处理，不能标作已验证引用。扫描 OCR 和精确文本引用的证据等级分开。

保存采用版本号/乐观锁，冲突不覆盖用户新笔记；网络失败保留内存草稿并显示未保存。主聊天发布使用幂等 id 和可重试提交，不能因两端写入失败而生成重复卡或丢失发现。不同标签页以服务端版本为准同步。

## 10. 性能、安全与退化

- PDF 在客户端 worker 渲染，只保留可见页与邻页画布；文档切换释放资源。按需支持经过鉴权的 Range 请求，先验证后端与代理的实际行为，不把响应 206 当现成功能。
- 每次访问同时校验账号归属、会话成员关系与文档绑定。PDF 内容不暴露公开别名，不将鉴权 token 写入 URL。禁用 PDF 脚本执行，外链协议白名单与安全打开。
- 会话启动、文档绑定、线程、发现、导出和删除均覆盖游客与登录账号边界。清小搭 `/v1` 保持原有契约，第一版工作台只属于 Web。
- 原文查看不等待模型；结构提取与重解析去重；VLM 只在需要时调用。沿用单 worker 与全局模型限流，新增交互不能压垮原聊天。
- 模型失败仍可看 PDF、选文、记笔记；结构失败仍可按物理页问答；定位不足显示页级来源。带密码或损坏的 PDF 给明确状态，不假装解析成功。
- 可访问性覆盖键盘翻页、可聚焦操作条、Esc 关闭弹层、屏幕阅读标签和减少动态效果设置。颜色之外使用图标/文字区分批注类别。

## 11. 分阶段交付与验收

A：先验证原版阅读与定位。完成会话/附件绑定、鉴权 PDF 内容、独立工作台、选区锚点、页码恢复。验证双栏、公式、表格、扫描、旋转页面与旧会话恢复；看原文不调用 LLM。

B：形成第一版完整闭环。专业翻译、选区追问、阅读线程、持久高亮/笔记、发现保存、发送回主聊天、答案返回原文。此阶段是第一版产品交付范围，不能只完成 PDF 预览就宣称工作台完成。

C：增强辨识度。图表/公式助读、逐步积累的术语与符号手册、单条主张证据核验、按目标的阅读路线、阅读成果导出。

D：同会话双论文问题对照与更完整的证据概览，根据前期使用情况迭代。

必要验收：刷新后准确恢复；翻译保留限定语/数字/引用；缩放和旋转后锚点一致；扫描页无伪精确选字；回答不串文档；取消与断线不污染主聊天；发送发现幂等；主聊天忙时排队正确；跨账号/跨会话读写均拒绝；会话删除清理阅读数据；PDF 查看在 LLM/VLM 不可用时正常。性能目标在实际测试文档和目标设备上建立基线后确定，不提前承诺未经测量的秒数。

验证使用合成或许可明确的测试 PDF，不提交用户论文。增加纯逻辑与接口测试、前端构建和关键交互测试；涉及真实模型的专业翻译与证据核验按授权单独评估。实现后才更新 README 和 docs/DESIGN.md 的已实现功能说明；本设计不改生产发布手册。
